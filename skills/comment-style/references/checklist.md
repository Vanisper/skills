# 注释检查清单

在提交或结束修改前，快速确认这些问题：

## 通用（任何语言）

- 这条注释是否解释了代码本身不容易看出来的信息（或为长逻辑提供导航），而不是复述代码
- 注释的去留是否用「读者收益 vs 维护成本」权衡过——自解释性按读者画像（语言背景、领域熟悉度）判断，不拿作者自己的熟悉度代替
- 是否掉进了「只给对外 API 写注释、模块 / 包内部裸奔」的默认倾向；内部非显然实现、阶段划分是否也照顾到了
- 是否反向滑向另一极端：拿注释补偿本该改掉的烂命名
- 第一行是否先说明“这是什么”
- 注释语言是否与项目主体语言对齐；外部 API 名、协议名、代码术语是否保留英文
- 同一组列表的句末标点是否统一（短语、词组、简短分句不加句末标点，完整句或复杂项可加）
- API 块注释是否按域组织（title / description / signature），**域之间是否空行**；description 是否用标签显式定位，而非只靠空行与 title 分隔
- title 用标题语法时层级是否符合从属关系（顶层符号高于成员）且项目内一致
- 字段、Props、options 的细节是否已经下沉到最小作用域，而不是堆在顶层注释里
- 主注释是否只说明整体对象，成员说明是否已经下沉到成员本身
- 公共 API 或非直观契约是否有块注释，且只写调用契约（参数、返回值、状态变化、失败条件、顺序规则），未塞架构取舍、模块边界或“不做什么”
- 使用的标签是否按四层裁决（规范依据 → 工具链现实 → 项目现状 → 口味）选择，与项目现有工具链、lint 规则、文档生成方式兼容
- 默认值是否已经由代码本身清楚表达；只有在确实需要时才额外补默认值说明
- TODO / FIXME 是否写明了原因和下一步，而不是只留空标记
- 注释掉的死代码是否已删除（历史交给版本控制）
- 有没有过时、空泛、范围过大的注释需要一起删除

## 分语言（按项目实际语言看对应组，可插拔）

### TypeScript / JavaScript

- 首导出符号是否单独写了 JSDoc，避免文件级注释被误挂到第一个导出
- 是否用了项目接受的 JSDoc / TSDoc 风格块注释，且未在一个项目里混出两套标签体系
- Vue 事件说明是否贴近真实事件来源（defineEmits 的 JSDoc 不被 hover 支持）；React 是否避免误用 `@emits`
- constructor parameter properties 的说明是否下沉到成员本身，而非堆在主注释

### Rust

- 条目注释是否用了 `///` 而非 `//`，模块级是否用了 `//!`
- 契约是否用 rustdoc 小节组织（`# Examples` / `# Errors` / `# Panics` / `# Safety`）
- doctest 示例是否真的能通过 `cargo test`

### Java / Javadoc

- 分段是否用 `<p>`、列要点是否用 `<ul>`/`<li>`、是否知道空行会被折叠
- `<ul>` 是否闭合；首行是否只写一句概要

### Python

- docstring 是否用 `"""` 且为模块 / 类 / 函数体的第一条语句
- 摘要行与后续描述之间是否空行；风格（Google / NumPy / reST）是否项目内统一不混
- 类型是否交给 type hints，docstring 未重复类型

### Go

- doc 注释是否为整句、以标识符名开头、紧贴声明无空行
- 导出标识符是否都有 doc comment；是否误用了 `@tag`（Go 无标签体系，契约写 prose）
- 示例是否写成 `ExampleXxx` 测试函数而非注释内代码块

### C#

- `<summary>` 是否只写一句，展开内容是否归位 `<remarks>`
- XML 是否良构（标签闭合、特殊字符转义）；泛型 cref 是否用花括号

### C / C++

- 块形态（`/**` vs `/*!` vs `///`）与命令前缀（`@` vs `\`）是否项目内统一
- API 文档是否写在头文件；指针出参是否标注了 `[in]` / `[out]` 方向

### Kotlin

- 弃用是否用 `@Deprecated` 注解而非 KDoc 标签（KDoc 无 `@deprecated`）
- 主构造器属性是否经 `@property` 登记；示例是否优先 `@sample` 引用

### PHP

- docblock 是否与原生类型声明重复（纯重复的删）；泛型集合等超集语法是否与项目所用静态分析器匹配
- `@throws` 是否补齐了会抛出的异常

### Shell

- 文件头是否写清用法、依赖、退出码
- 函数头是否写清各位置参数（`$1` / `$2`）含义、读写的全局变量、输出与返回码

> 新增语言时，在此加一个 `### <语言>` 组，与 [rules.md](rules.md) 路由表的 `lang/<语言>.md` 对应。
