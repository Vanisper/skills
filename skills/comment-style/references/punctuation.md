# 标点细则

> 本文件属作者风格偏好（仓库 README「偏好声明」已列明），不是通用规范；项目已有惯例时以项目为准。

## 语境区分

源码注释与文档正文是两种语境，标点规则不同：

- **源码注释**：力求精炼，只写契约、约束、边界、原因，不复述代码；中文注释一般不以句号结尾——句号是「成篇文章」的标点，而 API 注释是结构化卡片（见 [rules.md](rules.md)「注释的构成（域模型）」）：title 是定位短语、分点是精练碎片、signature 是契约事实，都不是句子；完整句子只通行于实现内的流程注释；成文整句惯例（Go / Python）优先，见 [rules.md](rules.md)「强语言惯例优先」
- **Markdown 文档正文**：是正常文章语境，按文章结构使用标点，不受上述注释标点规则约束

英文注释以项目现有风格为准，不必为了去标点而牺牲可读性（skill 补充惯例，非通用铁律）。

豁免：`@deprecated` 迁移说明、安全警告这类需要讲清「为什么 + 怎么办」的内容，可用完整句子。

## 列表标点

列表项的句末标点按语法结构判断：

- 短语、词组、简短分句不加句末标点
- 完整句，或含逗号、分号的复杂项，可加句号
- 同一组列表保持一致，不要一半加句号一半不加
