# AGENTS — AI 协作约定

## 本目录性质与边界

- 本目录是 {{workspace_purpose}} 的根工作空间（壳项目）：归集各项目、对齐规则、提供统一视角与总览；只承载文档、规划与工作空间约定，不包含项目代码。
- `projects/` 下的各项目仓库独立管理、不纳入根 git；进入具体项目开发时，遵循该项目自身的协作约定，本文件不辖。
- 各项目的边界与相互关系以 [docs/project-map.md](docs/project-map.md) 为准，动手前先对照确认目标项目。

## 文档落点规则

- 新项目：先在 `docs/projects/<项目名>/README.md` 立项总领，再展开其他内容。
- 同一项目的具体问题 / 业务 / 领域讨论：在该项目同目录下另立 `.md` 文件，不塞进总领 README。
- 业务札记：统一放 `docs/business/`。
- 项目之外的记录（随笔、心得、见闻等）：统一放 `docs/blog/`。
- skills：统一放根目录 `skills/` 下；对应 skill 的指令优先于本文件的一般约定。

## 跨项目工作方式

- 动手前先区分目标项目与参考项目：改动只落在目标项目，参考项目仅用于查阅既有实现。
- 不凭名称猜测接口、参数或行为：至少追到一处真实定义、调用或方法签名再动手。
- 在目标项目内按其既有目录结构、封装方式与代码习惯实现，不把参考项目的风格原样搬入。
- 多个项目的实现存在冲突时，先说明差异，再按指定的目标落地。

## 改动规则

- 只修改指定的目标项目；参考项目默认只读，除非用户明确要求一起改。
- `projects/` 下各子项目 git 彼此独立：改动前分别检查相关子项目的 `git status --short --branch`；根仓库的 git 状态不代表任何子项目。
- 不回退、不清理用户已有的未提交改动。

## 写作约定

- 书写语言与项目主体语言风格对齐（本工作空间以 {{primary_language}} 为主体语言）；工具名与专有术语保留原文。
- 精炼、直接，不写口水话、不写过程性叙述；每份文档一级标题唯一。
- 未决事项显式收进「待探讨」小节（列表形式），不写成含糊的肯定句。
- 不发明发起人未给出的决定：技术选型、依赖库、时间表等一概不写死。
- 标点、列表与源码注释的具体规范见 [docs/style-guide.md](docs/style-guide.md)，该规范同时是各项目仓库的默认书写与注释规范。

## 提交规范

- 遵循 Conventional Commits。
- type 与 scope 用英文——scope 与 type 一样可能进入流水线等自动化判断，非英文存在近义词不统一的问题；subject 可用 {{primary_language}}。
- header（`type(scope): subject` 整行）不超过 72 字符。
- 复杂改动按需补充 body；body 中有序、无序列表按需使用。
