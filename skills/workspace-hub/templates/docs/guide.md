# 工作空间使用指南

面向在本工作空间中参与规划、写作与开发的人。AI 协作方面的对应约定见 [../AGENTS.md](../AGENTS.md)。

## 工作空间的运作方式

- 本仓库（{{workspace_name}} 根工作空间）只管理文档与规划，不承载任何项目代码。
- 具体项目采用多仓库形态：各项目独立建仓，托管平台与存在形式不限——多平台仓库、本机既有项目皆可，可用可操作即可；以 clone 或链接（symlink 等）方式挂到本工作空间的 `projects/` 目录下使用。
- `projects/` 下的内容不纳入根仓库的 git 管理（已由 `.gitignore` 排除），各项目仓库的版本控制彼此独立。
- 项目文档写在根仓库的 `docs/projects/<项目名>/` 下；项目仓库建立后，工程内文档归项目仓库，规划与跨项目关系仍留在这里。

## 新项目立项流程

1. 在 `docs/projects/<项目名>/` 下撰写 `README.md`，说明项目定位、动机与待探讨事项（项目名先按暂定名处理并查重）。
2. 在文档中充分讨论，待方向成熟后创建对应仓库（默认放在 {{default_repo_home}} 下，不强制）。
3. 将仓库以 clone 或链接方式挂到 `projects/` 目录。
4. 在 [project-map.md](./project-map.md) 中登记该项目（定位、状态、与其他项目的关系）。

## 文档撰写与放置约定

- 书写语言与项目主体语言风格对齐（本工作空间以 {{primary_language}} 为主体语言）；工具名与专有术语保留原文。
- 精炼、直接：不写口水话，不写过程性叙述；每份文档只有一个一级标题。
- 未决事项显式收进「待探讨」小节（列表形式），不写成含糊的肯定句；不发明尚未做出的决定（技术选型、依赖库、时间表等）。
- 暂定名项目在每份文档首次出现时标注「（暂定名）」。
- 放置规则：
  - 跨项目的通用文档放在 `docs/` 顶层；
  - 单个项目的文档放在 `docs/projects/<项目名>/` 下，总领文件为 `README.md`，专题另立文件；
  - 产品/业务层面的思考札记放在 `docs/business/` 下；
  - 项目之外的记录（随笔、心得、见闻等）放在 `docs/blog/` 下。
- 文档互链一律使用相对路径。
- 标点、列表与源码注释的细则见 [style-guide.md](./style-guide.md)。

## scripts/ 的定位

`scripts/` 是预留的工作空间级脚本目录，用于放置服务整个工作空间的脚本（如批量拉取/挂载、状态巡检等）。当前为空，具体内容待需求出现后再补充。
