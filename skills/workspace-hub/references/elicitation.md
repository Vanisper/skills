# 分阶段问询清单

问询纪律见 [SKILL.md](../SKILL.md)：一次一问、每问附推荐答案、事实靠勘察、决策归用户。每阶段末输出小结并确认后再进入下一阶段；勘察已得的事实直接写进小结，不再提问。

## 阶段 1：定位与愿景

- 体系/工作空间叫什么名字？（推荐：沿用已有的组织名或目录名）
- 一句话定位或口号是什么？
- 主体语言（文档与注释的语言基准）？（推荐：按用户对话语言）
- 壳仓库是否推远端、托管在哪？（推荐：用户常用平台；不强制，可用可操作即可）

## 阶段 2：项目清单与关系

- 有哪些项目（含规划中的）？各自一句话定位？
- 哪个是核心、哪些是辅助或延展？相互关系如何（依赖、集成、候选集成）？
- 有无跨项目的共性约束（目标平台、技术基调等）？
- 有没有要立即展开的优先项？

## 阶段 3：仓库形态与挂载

- 多仓库还是 monorepo？（推荐：多仓库——壳模式为此设计；用户坚持 monorepo 时说明本方法收益有限，确认是否继续）
- 各项目现状：已存在（本机路径 / 云端地址）还是待创建？
- 挂载方式逐项目确认：clone 还是链接？（推荐：本机已有项目用链接，云端项目用 clone）
- 新建仓库的默认归属（组织 / 个人账号）？（推荐：不强制，登记为默认即可）

## 阶段 4：约定

- 提交规范？（推荐：Conventional Commits，type 与 scope 用英文，subject 随主体语言，header ≤ 72 字符）
- 书写与注释规范？（推荐：套用 templates/docs/style-guide.md，按主体语言调整细则）
- 文档落点是否采用默认结构（docs/projects 立项文档、business 业务札记、blog 项目外记录）？
- 初始「待探讨」清单：把问询中悬而未决的点归集登记到对应文档。
